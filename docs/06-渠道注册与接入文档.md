# 渠道注册与接入文档

本文档依据运行库 `dist/data/gateway.db` 中**实际启用**（`enabled=1` 且 `is_template=0`）的渠道生成，汇总每个上游渠道的注册流程、API Key 获取方式、接入参数与并发/限流配置，帮助你开通并接入网关。

「渠道」= 一个上游 AI 平台账号。网关聚合所有渠道，对外统一路由。创建渠道时需提供 `name`、`base_url`、`api_key`、`models`，并可选配 `max_concurrency`（并发上限）与 `min_interval_ms`（同一模型最小间隔，毫秒）。

## 三、自动同步渠道（无需手动注册）

网关内置**自动发现 + 健康保活**的免费渠道（`backend/core/zen_sources.py`，由 `config.py` 开启，默认 `True`）：

| 渠道名 | 数据来源 | 说明 |
|--------|----------|------|
| `opencode` | OpenCode Zen 免费模型目录 | 每隔 `ZEN_SYNC_HOURS`(6h) 自动拉取并真实探测；连续失败 `ZEN_PROBE_FAIL_LIMIT`(2) 次的模型自动移出渠道；每小时 `ZEN_HEALTH_CHECK_MINUTES`(60) 保活探测 |

同时，外部免费源 JSON 清单（`FREE_SOURCE_AUTO_SYNC`，默认开启）会每隔 `FREE_SOURCE_SYNC_HOURS`(6h) 拉取并与本地 `backend/data/provider_templates.json` 合并，新增的免费服务商自动进入「添加渠道」模板池。

> 提示：`provider_templates.json` 中的条目只是「可选模板」，是否实际接入以数据库 `providers` 表 `enabled=1` 为准。

## 四、如何把渠道接入网关

### 方式一：管理面板（推荐）

1. 进入「渠道管理」→「添加渠道」。
2. 若模板池存在对应模板（NVIDIA、魔搭等）可直接「模板一键添加」；或手动填写渠道名、Base URL、API Key。
3. `models` 可留空，网关会用密钥自动请求 `GET {base_url}/models` 拉取（`auto_fetch=true`）。
4. 按需设置渠道并发上限 `max_concurrency` 与同一模型最小间隔 `min_interval_ms`（留空用全局默认，或参照上表各渠道实测值）。
5. 保存后网关校验密钥有效性；校验失败仍可保存，但需手动补填模型列表。

### 方式二：直接操作数据库

按 `Provider` 表结构（`backend/models/__init__.py`）写入一条记录，字段包括 `name`、`base_url`、`api_key_encrypted`（AES-256-GCM 加密）、`models`、`free_only`、`enabled`、`max_concurrency`、`min_interval_ms` 等。

> **常见遗漏**：直接写库时务必设置 `is_template=0` 且 `enabled=1`，否则渠道不会参与实际路由。

### 客户端调用

```bash
curl -X POST http://127.0.0.1:8765/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的网关Key>" \
  -d '{
    "model": "NVIDIA-deepseek-ai/deepseek-v4-flash-0731",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

`model` 填「渠道名-模型名」直接走该渠道，或填「路由组名」实现组内故障切换 / 负载均衡。

## 五、注意事项汇总

1. **免费/付费标记**：`free_only=true` 的渠道会被当作免费源参与自动同步与免费路由。AMD Token Factory、OpenRouter 虽含免费额度但按量计费，`free_only` 设为 `false`。
2. **Base URL 差异**：各渠道端点不同（NVIDIA/魔搭/OpenRouter 为 `/v1` OpenAI 兼容；SenseNova 为 `/token.sensenova.cn`；Agnes 国内镜像为 `api.agnes-ai.cn`，国际站为 `apihub.agnes-ai.com`），按上表地址填写。
3. **并发与限流**：各渠道按数据库实测配置（见第一节），免费渠道普遍并发 4/间隔 300ms，按量渠道并发 6/间隔 200ms；避免触达上游 RPM 上限。
4. **密钥安全**：所有渠道 API Key 加密落库（`api_key_encrypted` 字段，AES-256-GCM），请求转发时才解密；勿在日志、版本库或前端代码中暴露明文。
5. **模型可用性**：`disabled_models` 内的模型（如 NVIDIA 的 `phi-3-vision-128k-instruct`、`glm-5.2`、`deepseek-v4-flash-0731`）已被禁用，接入/组路由时需避开。
6. **自动同步**：`opencode` 等自动渠道的连接与模型数量由定时任务维护，一般无需人工干预；同步失败会保留现有渠道不覆盖（防误清）。
